# v0.3 Execution-Ready Project Secretary

v0.3 upgrades ProjectNavigatorMCP from plan-and-guard navigation to an execution-ready project secretary.

The focus is not richer AST parsing. The focus is deterministic task execution support:

- explain guard failures with repair recipes;
- rerank execution plans to the most relevant 5-8 steps;
- apply domain gates to demote unrelated paths and commands;
- protect dirty worktrees with explicit edit boundaries;
- infer useful targets from non-frontmatter Markdown plans;
- record completed task results as reusable project memory.

## Validation Scenario

For the Flutter role visual design-system task, `prepare_task_context` should rank:

1. the direct guard failure file and line;
2. the canonical design-system theme/token file;
3. the guard implementation script;
4. narrow guard validation commands;
5. broader design-system validation only after narrow checks.

Backend, database, Maestro, Patrol, and screenshot commands should be demoted unless the task or source document explicitly asks for them.
